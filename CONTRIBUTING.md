CONTRIBUTING TO UNITY DIALOGUE SYSTEM

Thank you for your interest in contributing to the project. The purpose of the project
is to provide Unity developers with a simple, reusable, and customizable framework for creating
dialogue in their games. Contributions of all sizes are welcome.

Ways to Contribute

There are several ways to contribute:

* Reporting current bugs
* Suggesting new features
* Improving documentation
* Fixing issues
* Improving on existing code by optimizing
* Adding tests
* Creating examples

Reporting Bugs

A useful bug report has:

* A clear description of the issue
* The behavior that was expected
* the behavior received
* Steps that can be used to reproduce the issue
* The version of Unity used
* Relevant error or console messages
* Screenshot if applicable

Suggesting New Features

Feature suggestions are very welcome, please create a GitHub Issue describing the feature you want implemented.
A feature suggestion should explain what the feature would do and why it'd be useful.

Making a Contribution

To contribute code or documentation:

1. Fork the Unity Dialogue System Repo
2. Clone your fork to your computer
3. Create a new branch for your changes
4. Make and test the changes
5. Commit the changes with a description
6. Push the branch to your fork
7. Open a pull request

Code Style and Format

Unity Dialogue System is primarily made with C# and Unity Visual Scripting. Contributions should follow
consistent C# and Unity coding practices.

When contributing:

* Use clear names for classes, methods, groups, variables, and properties
* Use consistent indentation or positioning
* Avoid unnecessary complexity
* Add comments when aplicable
* Remove debugging code and console code

Testing Requirements

Contributors should test their changes before opening a pull request.

For code changes make sure that the unity project opens without new errors, existing functionality continues to work, and that the new or modified code works as expected.

If a change requires specific manual testing inside Unity please describe the testing process and results in the pull request.

Documentation Standards

New features and significant changes need to be documented.
Documentation should clearly explain what a feature does and how another developer can use it.
Code examples are encouraged.

Pull Request Review

Pull requests will be reviewed before they are merged. You may be asked questions about your request or what you're adding.

Community Expectations

* Be respectful of different experience levels
* Provide constructive feedback
* Keep discussions relevant to the project
